# Морская доставка 🌊 — Telegram-бот ивента

Самостоятельный Telegram-бот для ролевого текстового ивента с мини-игрой в стиле торговой экспедиции между островами (механика в духе ивентов Cookie Run: Kingdom). Игроки помогают торговцам с острова **Парламумти** доставлять товары между островами, проходя игровое поле с клетками-испытаниями. Всё взаимодействие — через инлайн-кнопки.

## Возможности

- **Остров Парламумти** и 5 торговцев: Аскен, Марта, Эролез, Пасец, Иискал.
- 8 предметов; у каждого торговца есть свой товар и потребность в товаре с другого острова.
- В каждом раунде случайно выбираются **2 торговца**, которым нужна доставка.
- **5 раундов** за ивент; раунды запускает администратор вручную. Набор в раунд длится **1 час**, максимум **12 игроков**.
- Игровая сессия: **17 ходов**, не более **7 перемещений** между островами. Каждое действие тратит ход; когда ходы кончаются — сессия завершается.
- **Игровое поле** из клеток: пустая (ничего), сокровище (бонус + автоматический рывок на 2 клетки), испытание (мини-игра). Расположение случайно, не более **3 испытаний** за сессию.
- **3 мини-игры-испытания** (при провале — шаг назад):
  1. **Поиск безопасных клеток** — 6 кнопок, 3 безопасных / 3 бомбы, нужно открыть все безопасные.
  2. **Рыбалка** — через случайное время появляется кнопка «ЖМИ!», успеть нажать за ограниченное время.
  3. **Побег от акулы** — выбор безопасного направления несколько ходов подряд.
- Интерфейс показывает: оставшиеся ходы, текущую позицию, выполненные заказы, активные запросы торговцев, полученные бонусы.
- **Админ-панель**: запуск/завершение раундов, статистика игроков и по раундам (игры, заказы, успешные/проваленные испытания, ходы, перемещения), рейтинг, экспорт в CSV.
- **Таблица лидеров** по итогам всех раундов и **финальный рейтинг** после 5-го раунда.
- Реакция только на сообщения с хештегом **`#морскаядоставка`** — без него бот не читает сообщение и не реагирует.
- Состояние сохраняется в БД (**SQLite** локально или **PostgreSQL** в продакшене); поддержка нескольких игроков одновременно.

## Команды

**Игроку**

| Команда                          | Описание                              |
|----------------------------------|---------------------------------------|
| `/sea`                           | Открыть меню ивента / текущую сессию  |
| сообщение с `#морскаядоставка`   | То же, что `/sea`                     |
| `/start`, `/help`                | Справка                               |
| `/chatid`                        | Показать ID текущего чата             |

**Администратору чата** (владелец/админ группы; либо `OWNER_ID`)

| Команда            | Описание                                       |
|--------------------|------------------------------------------------|
| `/sea_panel`       | Панель управления ивентом (кнопки)             |
| `/sea_open`        | Открыть набор в следующий раунд (на 1 час)     |
| `/sea_round`       | Запустить раунд и опубликовать запросы          |
| `/sea_endround`    | Завершить текущий раунд и показать итоги        |
| `/sea_players`     | Список записавшихся на раунд                    |
| `/sea_stats`       | Полная статистика игроков (рейтинг)            |
| `/sea_roundstats N`| Статистика по раунду N                          |
| `/sea_final`       | Финальный рейтинг по итогам всех раундов        |
| `/sea_export`      | Экспорт статистики в CSV                        |
| `/sea_newevent`    | Сбросить ивент и начать заново                  |

## Как проходит ивент

1. Админ открывает набор: `/sea_open` (или кнопка в `/sea_panel`). В чат публикуется лобби с кнопкой «⚓ Записаться» на 1 час, максимум 12 игроков.
2. Игроки записываются. Затем админ запускает раунд: `/sea_round` — бот публикует 2 запроса торговцев.
3. Игрок открывает `/sea`, начинает сессию и через кнопки плывёт по маршруту, берёт заказы, проходит испытания.
4. После раунда админ завершает его: `/sea_endround` — показываются итоги раунда.
5. Повторить для 5 раундов. После последнего — `/sea_final` для финального рейтинга. `/sea_export` выгружает CSV.

## Запуск локально

```bash
# 1. Установка (Python 3.11+)
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# 2. Настройте окружение
cp .env.example .env
# отредактируйте .env и впишите BOT_TOKEN от @BotFather

# 3. Запуск (long-polling)
set -a; source .env; set +a
python -m seadelivery_bot
```

По умолчанию состояние пишется в файл `seadelivery.db` (SQLite). Для Postgres задайте `DATABASE_URL`.

### Добавление бота в группу

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. У @BotFather: `/setprivacy` → **Disable** (чтобы бот видел сообщения с хештегом в группе).
3. Добавьте бота в группу и выдайте права администратора (нужно, чтобы определять администраторов для админ-команд).
4. Узнайте ID чата командой `/chatid`. При желании ограничьте бота через `ALLOWED_CHAT_IDS`.

Команды можно зарегистрировать у @BotFather через `/setcommands`:

```

sea_round - Админ: запустить раунд
sea_endround - Админ: завершить раунд
sea_players - Админ: записавшиеся
sea_stats - Админ: рейтинг игроков
```

## Деплой

Помимо polling есть FastAPI-приложение для webhook-режима (`POST /webhook` для Telegram, `GET /` и `GET /healthz` для healthcheck). Локально:

```bash
# Переменные: BOT_TOKEN, DATABASE_URL, WEBHOOK_URL (или авто на Render/Fly.io)
uvicorn seadelivery_bot.webhook_app:app --host 0.0.0.0 --port 8080
```

### Render.com (бесплатный 24/7) + Neon Postgres

Проект содержит готовый `render.yaml` (Blueprint), `Dockerfile` и `main.py` (`uvicorn main:app`).

1. **Залейте код в Git-репозиторий** (GitHub/GitLab), который сможет подключить Render. Это отдельный проект — заведите для него новый пустой репозиторий и запушьте содержимое архива.
2. **Создайте бесплатную базу на [Neon](https://neon.tech)** (Sign in with GitHub):
   - **New Project** → Postgres 16, любой регион.
   - **Connection Details** → скопируйте строку **Pooled connection** (`postgresql://...?sslmode=require`).
3. **Зарегистрируйтесь на [Render](https://render.com)** (через GitHub или email, карта не нужна).
4. **New → Blueprint** → подключите ваш репозиторий. Render прочитает `render.yaml`.
5. В настройках сервиса задайте секреты:
   - `BOT_TOKEN` — токен нового бота от @BotFather.
   - `DATABASE_URL` — строка подключения Neon (вместе с `?sslmode=require`).
6. Дождитесь деплоя. Health-check на `/healthz` должен стать зелёным; `WEBHOOK_URL` вычисляется автоматически из `RENDER_EXTERNAL_URL`, webhook регистрируется на старте.
7. Чтобы сервис не засыпал (free-tier Render засыпает после 15 минут простоя):
   - Зарегистрируйтесь на [UptimeRobot](https://uptimerobot.com) (бесплатно).
   - **Add new monitor** → HTTP(S) → URL: `https://<имя-сервиса>.onrender.com/healthz` → интервал 5 минут.

Состояние игры (раунды, регистрации, сессии, статистика) хранится в Neon и переживает любые перезапуски/редеплои Render. Если `DATABASE_URL` не задан, бот падает на локальный SQLite (`DB_PATH`), который на free-tier Render обнуляется при каждом редеплое — только для тестов.

### Docker (свой VPS)

```bash
docker build -t seadelivery-bot .

docker run -d --name seadelivery-bot \
    -e BOT_TOKEN=YOUR_TOKEN \
    -e DATABASE_URL=postgresql://user:pass@host/db?sslmode=require \
    -e WEBHOOK_URL=https://your-domain.example.com \
    -p 8000:8000 \
    seadelivery-bot
```

`WEBHOOK_URL` должен указывать на публичный HTTPS-адрес контейнера (через reverse-proxy с TLS).

## Переменные окружения

| Переменная         | Назначение                                                        |
|--------------------|-------------------------------------------------------------------|
| `BOT_TOKEN`        | **Обязательно.** Токен бота от @BotFather.                        |
| `DATABASE_URL`     | Postgres URI для продакшена. Если пусто — SQLite.                 |
| `DB_PATH`          | Путь к SQLite-файлу (если `DATABASE_URL` пуст). По умолч. `seadelivery.db`. |
| `OWNER_ID`         | Telegram user ID супер-владельца (права админа во всех чатах).     |
| `ALLOWED_CHAT_IDS` | Список chat_id через запятую/пробел. Пусто = любой чат.           |
| `WEBHOOK_URL`      | Только webhook: публичный HTTPS-URL приложения.                   |
| `WEBHOOK_SECRET`   | Только webhook: секрет для проверки колбэков (необязательно).      |

## Структура проекта

```
src/seadelivery_bot/
  content.py     # константы баланса и контента (острова, торговцы, предметы, награды)
  models.py      # enum'ы и dataclass'ы состояния (JSON-сериализуемые)
  engine.py      # чистая игровая логика (поле, ходы, 3 мини-игры) — без aiogram/БД
  store.py       # SeaStore: персистентность SQLite + PostgreSQL
  service.py     # жизненный цикл события: набор, раунды, сессии
  ui.py          # инлайн-клавиатуры и рендер статуса
  handlers.py    # роутер игрока (#морскаядоставка-гейт, геймплей, колбэки мини-игр)
  admin.py       # роутер админа (панель, статистика, экспорт)
  basic.py       # /start, /help, /chatid
  config.py      # конфиг из переменных окружения
  middlewares.py # whitelist чатов
  bot.py         # запуск polling
  webhook_app.py # FastAPI-приложение для webhook
main.py          # точка входа uvicorn main:app (деплой)
Dockerfile       # образ для Render / VPS
render.yaml      # Render Blueprint (webhook + healthcheck)
tests/           # тесты движка, хранилища и жизненного цикла
```
